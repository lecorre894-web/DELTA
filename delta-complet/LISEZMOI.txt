Δ1 V0.1 — émulateur Δ-QI-V à intrication flottante et proportionnée

LANCER (Termux, une ligne chacune)
  pkg install python && pip install numpy
  python bench.py
  python bench_C.py

FICHIERS
  delta1.py       le moteur Δ1 (individualisme, îlots, fusion, redécoupage
                  par test de Schmidt, seuil ε, facteur %, mesure)
  bench.py        validation contre simulateur exact + passage à l'échelle
  bench_C.py      double intrication (exact / flottant ε) et proportionné
  *_log.txt       les chiffres obtenus lors de l'exécution de référence
  *.json          les mêmes chiffres, lisibles par machine

LES DEUX NIVEAUX D'INTRICATION
  niveau 1 exact    : un îlot est redécoupé seulement si la coupure est
                      rigoureusement séparable (Schmidt rang 1). Zéro erreur.
  niveau 2 flottant : un îlot est redécoupé si le poids jeté est <= ε.
                      L'erreur est comptabilisée (fidélité estimée).

LE FACTEUR % (proportionné)
  ε_i = ε · (1 - P_i).  P = 100 % : jamais tronqué.  P = 4 % : tronqué au besoin.
  deux règles testées pour décider une coupure :
    strict  : le qubit le plus important de l'îlot décide -> sûr, mais bloque
              toute compression dès qu'un qubit à 100 % est dans l'îlot
    detache : seuls les qubits du bloc détaché décident -> compresse et protège
              quand même les qubits importants (voir bench_C_log.txt)

PROPRIÉTÉ EXACTE UTILISÉE
  une porte sur (a,b) ne modifie que les coupures qui séparent a de b.
  Δ1 ne teste que celles-là : ce n'est pas une heuristique.

LIMITE DURE
  le coût est fixé par le PIC de k au cours du circuit, pas par l'état final.
  un état très intriqué (GHZ, circuit aléatoire profond) ramène k à n :
  Δ1 exact coûte alors exactement autant qu'un simulateur 2^n classique.
  avec 64 Gio, le mur exact se situe vers k = 31-32.

Δ2 V0.2 — liens χ, intrication faible, lots, complex64 (delta2.py)

  python bench2.py

  Δ1 coupait au rang 1 : fidélité 0.62 à 1000 qubits.
  Δ2 garde χ valeurs de Schmidt par lien (forme de Vidal Γ-λ, famille MPS/TEBD).
  μ_j du canon Δ = χ du lien. Toute une couche de portes = un seul lot.

  RÉSULTATS DE RÉFÉRENCE (bench2_log.txt)
    vérité terrain n=16 : χ=4 exact à profondeur 10, fidélité 0.99936 à profondeur 40
    1 000 000 qubits, θ=0.6, profondeur 10, χ=4 :
        259 Mio, 106 s, ~141 000 portes/s, fidélité globale estimée 0.99927
        (un vecteur d'état 2^n demanderait 10^301031 octets)

  LIMITE DURE
    ça marche parce que l'intrication de chaque coupure reste bornée (loi d'aire,
    1D, voisins proches, faible profondeur). Intrication forte ou longue portée :
    χ requis ~ 2^(n/2), on retrouve le mur. Ce n'est pas un avantage quantique :
    ces circuits sont faciles pour un ordinateur classique PAR CONSTRUCTION.
    la fidélité estimée n'est vérifiée contre la vérité exacte qu'en n=16.

Δ4 V0.4 — la GRAPPE PARTAGÉE : chaîne infinie (delta4.py)

  python bench4.py

  une seule cellule de 2 tenseurs représente une chaîne INFINIE de qubits.
  contrôle : <Z> du qubit infini comparé au centre de chaînes finies Δ2.
    profondeur 10 : infini 0.85995244 (16 Kio, 5 ms) = fini n=4000 (32 Mio, 3.7 s)
                    écart 7e-15
    profondeur 20 : infini 0.54265124 = fini, écart 5e-11
  pourquoi c'est exact : à profondeur d, l'influence ne voyage que de d sites
  (cône de lumière) ; le centre d'une longue chaîne ne voit jamais ses bords.

  PRIX : l'individualisme est suspendu. Toutes les grappes sont identiques et
  le circuit doit agir pareil partout. Modifier un qubit précis casse le
  partage à cet endroit : « l'individualité coûte ce qu'elle modifie ».

Δ9 V0.9 — SVD randomisée gardée, ECC, reprise, distribué (delta9.py)

  python bench9.py   python bench9b.py   python bench9c.py

  ECC — CE QUI MARCHE, ET BIEN
    découpe en parts d'OCTETS égales + parité XOR : surcoût exactement 1/N
      2 nœuds 50 % | 4 nœuds 25 % | 8 nœuds 12,5 % | 16 nœuds 6,2 %
    CRC32 par part : une corruption d'UN SEUL octet est détectée
    perte totale d'un nœud : reconstruit IDENTIQUE AU BIT PRÈS, état remonté
      strictement égal à l'original
    tolérance : une panne simultanée. Deux nœuds perdus -> il faudrait
      Reed-Solomon (piste V1.0).

  SVD RANDOMISÉE — CONSTAT NÉGATIF, ASSUMÉ
    avec garde-fou et k prédictif, sur le circuit monstre n=32 :
      exacte    : 0.76 s, 155 décompositions exactes
      randomisée: 1.02 s, dont 29 rattrapées sur 45 tentatives
    le garde-fou se déclenche trop souvent et fait le travail DEUX fois.
    De plus, la SVD randomisée ne renvoie que k+marge valeurs : sans garde-fou
    elle PLAFONNE X en silence (c'est ce qui donnait l'illusion d'un gain :
    moins de mémoire parce qu'on tronquait davantage, sans le dire).
    -> alea=False par défaut. Le hasard n'est rentable que si X reste petit
       devant la matrice, ce qui n'est pas le cas sur les circuits durs.

  REPRISE SUR SATURATION — MÉCANISME INUTILE EN L'ÉTAT, ASSUMÉ
    'arret' et 'reprise' finissent au MÊME seuil (2560 Kio) avec 0 reprise.
    Explication : quand c'est le budget GLOBAL qui mord, étendre mu d'un lien
    ne crée pas de mémoire. Et quand seul mu limite, Δ8 l'étend déjà tout seul.
    Le code reste, documenté comme sans effet mesurable.

Δ11 V1.1 — TRAVAIL À LA DEMANDE, économie d'énergie (delta11.py)

  python bench11.py    python bench11b.py

  TROIS MÉCANISMES
    portes inertes  : une porte à distance <= tol de l'identité est sautée
    qubits au repos : un site que rien n'a touché ne coûte rien
    cône de lumière : pour une question sur quelques qubits, Δ ne calcule que
                      leur passé ; le reste du registre ne se réveille jamais

  RÉSULTATS (écart sur les réponses : 0, à la précision machine)
    registre endormi à 90 % (n=400) : 2394 portes -> 253 portes,
      102 ms -> 12 ms, 88,7 % d'énergie économisée
    cône de lumière, qubits interrogés dans une zone ACTIVE :
      n=   200 : 50 portes -> 23,  64,8 % d'énergie économisée
      n= 1 000 : 275 -> 24,        85,8 %
      n= 4 000 : 1050 -> 23,       97,1 %
      n=20 000 : 5175 -> 24,       99,0 %
    le coût d'une question devient CONSTANT (~24 portes) quelle que soit la
    taille du registre : seul compte le cône, pas le nombre de qubits.

  HONNÊTETÉ SUR L'ÉNERGIE
    aucune mesure électrique n'est possible ici. L'énergie est une ESTIMATION :
    puissance typique (2 W, téléphone) x temps de calcul effectif. Ce qui est
    réellement mesuré, ce sont les portes exécutées, les flops et le temps.
    Un cas du premier banc d'essai affiche une économie x60 000 000 : c'est un
    artefact (les qubits interrogés n'avaient aucune porte active dans leur
    passé, Δ a répondu sans rien calculer). bench11b.py donne le cas honnête.

  RÉSULTAT PRINCIPAL — source lente d'ENTRÉE-SORTIE (300 µs, cas disque/réseau)
    LRU sans prédiction   : 0.27 s | 454.6 µs/accès |  0.0 % de succès

    -> x3.03 en temps total, latence divisée par 3.2

    taux de succès 98 à 99.8 %, latence d'accès 69.8 -> 3.1 µs (x22),

    celui qui calcule les données. Sur une machine à plus de cœurs, ou quand
    la lenteur vient d'une attente (disque, réseau), le gain est réel ; quand
    elle vient du calcul, le préchargement ne crée pas de temps.

    sans ces trois corrections, le cache prédictif était plus LENT que le LRU.

Δ19 V1.9 — Δ-X3D : 256 NIVEAUX DE CACHE (delta19.py)

  python bench19.py

  DEUX IDÉES, ET ELLES TIENNENT ENSEMBLE

  1) RÉPERTOIRE GLOBAL -> le nombre d'étages ne coûte RIEN en latence.
     Un cache matériel s'arrête à 3 ou 4 niveaux parce qu'il les interroge
     l'un après l'autre : chaque étage ajoute sa latence. Δ tient un
     répertoire unique (adresse -> étage) : UNE seule recherche, que la pile
     ait 3 étages ou 256.
     MESURE : 3 étages 4,40 µs/accès | 256 étages 4,39 µs/accès. Le coût du
     nombre d'étages est donc nul, et c'est vérifié, pas supposé.

  2) L'ÉVICTION DEVIENT UNE DÉGRADATION -> plus rien n'est jamais perdu.
     Quand un étage déborde, sa ligne la plus froide ne disparaît pas : elle
     descend et y est stockée plus grossièrement (16 -> 8 -> 4 -> 2 bits par
     chiffre). Une donnée très ancienne finit floue, mais PRÉSENTE.
     MESURE (même parcours) : Δ garde toutes les lignes, erreur 2,9e-07 sur
     les plus vieilles ; le cache classique à 3 niveaux en perd 1 116
     DÉFINITIVEMENT.

  LE % PROTÈGE : après 1 200 lignes, les lignes à 100 % sont TOUTES encore
    à l'étage 0 (le plus rapide) ; les lignes ordinaires du même âge sont
    déjà descendues.

  CAPACITÉ APPARENTE (capacité géométrique, facteur 1,3)
     64 étages -> 15,6 Tio | 128 étages -> 291 Eio | 256 étages -> 10^11 Yio
    C'est une capacité de PLAN, pas de silicium : elle dit jusqu'où la
    hiérarchie peut s'étendre sans changer d'algorithme, rien de plus.

  CORRECTIONS FAITES EN COURS DE ROUTE
    1. la cascade ne déplaçait qu'une ligne par étage -> corrigée
    2. l'affichage des grandes capacités renvoyait None au-delà du Tio

  « On peut tout fondre en un seul. » C'est fait. Δ-UN est une seule classe
  qui tient les quatre couches, et TROIS RÉGLAGES, rien d'autre :
      eps   ce qu'on a le droit de PERDRE
      P (%) ce qui COMPTE : précision, priorité, protection
      mu    ce qu'on a le droit de DÉPENSER

      CALCUL   fond infini partagé + grappes allumées ....... Δ5 Δ14 Δ15
      CACHE    pile X3D 256 étages, répertoire global ....... Δ17 Δ19
      MÉMOIRE  pages dédupliquées + condensateurs ........... Δ13 Δ16 Δ18
      SCEAU    clé, Merkle, chiffrement, parité ............. Δ9  Δ18

  1. EXACTITUDE (l'épreuve qui compte avant toutes les autres)
     Δ-UN confronté à l'opérateur DENSE, sans aucune compression :
     erreur relative 4,5e-13 pour un eps demandé de 1e-8.
     Δ est plus exact que ce qu'on lui a demandé, et il le mesure lui-même
     (méthode .erreur()). Une brique qui ne sait pas dire son erreur n'a
     rien à faire dans Δ.

  2. DÉBIT, sur un problème de taille 10^18
     4 096 blocs = 524 288 inconnues en 0,138 s
     4,95 Gflops | 3,8 millions d'inconnues par seconde
     opérateur : 1 676 Kio, CONSTANT — la taille du problème n'y change rien.

  3. LE POINT DE FUSION : le lot nourrit le cache
     plage(..., cacher=True) : le gros calcul, fait UNE fois, remplit la
     hiérarchie. Les questions de détail qui suivent ne recalculent plus.
     succès : 48,5 µs | recalculer la même ligne : 1 309 µs -> x27.
     Sur la démonstration au large (cache non saturé) : 9,6 µs, 100 % de
     succès, zéro dégradation.

     ÉPREUVE À BUDGET ÉGAL — 2 Mio de lignes à loger dans 256 Kio, pas un
     octet de plus pour l'un que pour l'autre :
       Δ-X3D 256 étages  : 0 ligne oubliée, 100 % de succès, 147 ms
       cache classique 3 : 1 792 lignes PERDUES, 7,2 % de succès, 3 585 ms
     Mais Δ ne triche pas : ses vieilles lignes sont FLOUES. Mesuré selon la
     finesse la plus basse qu'une ligne ait connue :
       16 bits -> erreur médiane 2,3e-07   (pire 1,2e-06)
        8 bits -> erreur médiane 3,3e-04   (pire 1,9e-03)
        4 bits -> erreur médiane 3,8e-03   (pire 6,5e-02)
        2 bits -> erreur médiane 2,1e-02   (pire 3,3e-01)
     Le marché est donc clair et il est honnête : le classique répond juste
     ou ne répond pas ; Δ répond toujours, en disant de combien il est flou.
     Si l'exactitude prime, on laisse P à 100 % sur ce qui compte : ces
     lignes-là ne descendent jamais.

  4. MÉMOIRE : 512 pages écrites, 8 réellement stockées -> x64
     64,0 Mio bruts -> 9,0 Kio, intégrité vérifiée.
     condensateur 8 bits : 1 024 o -> 128 o (x8), erreur 6,6e-05.

  5. SCEAU : 256 blocs scellés et chiffrés en 5 ms (51 Mo/s — le débit est
     plus bas que les 739 Mo/s de Δ18 parce que les blocs font 1 Kio : c'est
     le coût FIXE par bloc qui domine, pas le hachage).
     preuve de Merkle du bloc 37 : vraie ; sur le même bloc altéré : fausse.
     nœud perdu reconstruit depuis la parité SANS déchiffrer les autres :
     oui. Coût de la parité : 0,39 % (1 bloc sur 256).

  6. CONTRE-ESSAI (celui qu'on n'a pas le droit de sauter)
     noyau purement aléatoire : rangs retenus 64 sur 64 possibles.
     AUCUNE compression. Le gain de Δ vient de la STRUCTURE, jamais de la
     magie. Sur des données sans structure, Δ-UN ne promet rien et ne gagne
     rien — et c'est exactement ce qu'il faut qu'il fasse.

  QUATRE CORRECTIONS FAITES PENDANT LA FUSION, TOUTES MESURÉES
    1. la cascade d'éviction traversait les étages un par un : 126 660
       dégradations pour 2 048 insertions, 362 µs par succès. Corrigée : la
       ligne froide saute DIRECTEMENT au premier étage libre.
       -> 2 043 dégradations, 48,5 µs. Gain x7,5, et le nombre d'étages
       redevient vraiment gratuit.
    2. une ligne qui remontait était ré-encodée en 16 bits alors que son
       information était déjà perdue : huit fois la place pour une précision
       imaginaire. Corrigée : en montant, la ligne garde sa finesse. Elle
       gagne en VITESSE, pas en finesse. La finesse perdue est perdue.
    3. relire-réécrire une ligne la dégradait un peu plus à chaque fois
       (perte de génération). Corrigée : à finesse égale, le condensateur est
       déplacé tel quel. Erreur des vieilles lignes de Δ19 : 7,6e-05 -> 2,9e-07.
    4. une page rangée à bas % passait en float16 et DÉBORDAIT en silence
       (valeurs infinies stockées comme si de rien n'était). Corrigée : Δ
       remonte d'un cran de précision et le déclare (compteur `relevees`).
       Une donnée fausse ne vaut pas mieux qu'une donnée absente.

  CE QUE Δ-UN NE FAIT PAS, ET IL FAUT LE DIRE
    - ce n'est pas un ordinateur quantique : c'est une émulation classique
      qui exploite la structure. Sur un problème sans structure, elle perd.
    - la capacité « 10^11 Yio » est une capacité de PLAN, pas de silicium.
    - la cryptographie est pédagogique (bibliothèque standard) : pour un

Δ-BTC V1.0 — TEST DE CONFORMITÉ CONTRE BITCOIN (delta_btc.py)

  données : btc_reference.json (API publique blockstream.info, 2026-09-23)

  POURQUOI CE TEST EST DIFFÉRENT DE TOUS LES AUTRES
    Jusqu'ici Δ a toujours été vérifié contre une référence QUE NOUS AVONS
    ÉCRITE : l'opérateur dense, le cache LRU, l'état exact. C'est nécessaire,
    mais insuffisant : on peut se tromper des deux côtés à la fois.
    Bitcoin est une référence EXTÉRIEURE, publique, figée depuis 2009 et
    recalculée en permanence par des dizaines de milliers de machines.
    Il n'y a pas de demi-réussite : une empreinte est juste, ou elle est
    fausse. C'est l'épreuve la plus dure qu'on ait fait passer à Δ.

  C1  EN-TÊTE -> HASH OFFICIEL ............................... CONFORME 4/4
      blocs 0, 100 000, 200 000, 968 000 : les 80 octets de l'en-tête,
      double SHA-256, redonnent EXACTEMENT le hash publié, au bit près.

  C2  RACINE DE MERKLE RECALCULÉE ............................ CONFORME 3/3
      393 transactions réelles rejouées. Le bloc 200 000 (388 tx) traverse
      cinq niveaux impairs, donc cinq duplications : 0,57 ms, racine exacte.

  C3  PREUVE DE TRAVAIL ...................................... CONFORME 4/4
      bloc 0 : 43 bits de zéros | bloc 968 000 : 79 bits de zéros.
      Chaque hash est bien SOUS la cible dérivée de nBits.

  C4  DIFFICULTÉ ............................................. CONFORME 4/4
      1,000000 au bloc 0 -> 132 757 073 449 487,52 au bloc 968 000,
      recalculée depuis nBits seul, identique à la valeur publiée.

  C5  PREUVE SPV ............................................. CONFORME 5/5
      prouver qu'une transaction est dans un bloc de 388 : 9 empreintes,
      288 octets au lieu de 12 416 -> x43. Acceptée sur le vrai txid,
      REFUSÉE sur un txid falsifié. C'est ce que fait un portefeuille léger.

  C6  Δ18 EST-IL CONFORME À BITCOIN ? ........................ NON, ASSUMÉ
      Δ18 : BLAKE2b-128 À CLÉ, octets tels quels.
      Bitcoin : SHA-256 deux fois, SANS clé, txid inversés.
      Ce n'est pas un défaut : les deux arbres répondent à des questions
      OPPOSÉES. L'arbre de Δ est fait pour qu'un tiers NE PUISSE PAS
      refabriquer la racine ; celui de Bitcoin pour que TOUT LE MONDE le
      puisse. Pour parler à Bitcoin, on utilise delta_btc.racine_merkle,
      vérifié conforme ci-dessus.

  C7  CVE-2012-2459 REPRODUITE PUIS CORRIGÉE ................. CONFORME
      3 transactions et 4 transactions (la 3e recopiée) donnent LA MÊME
      racine. C'est la vraie faille de Bitcoin de 2012 : un attaquant
      fabrique un bloc invalide portant la racine du vrai, le nœud le
      marque « déjà vu, invalide », puis refuse le VRAI bloc. Déni de
      service par confusion d'identité.
      Correctif (celui de Bitcoin Core) : si deux nœuds APPARIÉS et tous
      deux réellement présents sont identiques, l'arbre est muté -> rejet.
      Vérifié : le bloc truqué est rejeté, et AUCUN des 3 blocs réels
      (393 transactions) n'est rejeté à tort.

  C8  DÉBIT, ET CE QUE Δ N'APPORTE PAS ....................... LIMITE ASSUMÉE
      1,53 MH/s ici. Difficulté du réseau : 1,33e14, soit 5,70e23 essais
      attendus pour un bloc -> 1,2e10 ANNÉES à ce débit.
      ET C'EST LE POINT LE PLUS IMPORTANT DE TOUT LE PROJET :
      Δ ne peut RIEN pour le minage, et ne le pourra jamais. Son gain vient
      toujours de la STRUCTURE. Or SHA-256 est conçu, ligne par ligne, pour
      n'en avoir AUCUNE. C'est le contre-essai du noyau aléatoire de Δ-UN,
      mais mené par l'adversaire lui-même. Si quelqu'un prétend qu'une
      architecture « quantique » ou « Δ » mine plus vite : c'est faux, et
      ce banc le prouve chiffres en main.

  C9  LA FAILLE ÉTAIT AUSSI DANS Δ18 — TROUVÉE, ET FERMÉE
      Δ18 appariait lui aussi le dernier nœud impair avec lui-même. MESURÉ :
      5 blocs et 6 blocs (le dernier recopié) donnaient LA MÊME racine.
      La faille était donc RÉELLE dans notre code, pas seulement dans
      l'histoire de Bitcoin. Δ18 reçoit maintenant `strict=True` : le cas
      sain passe, le cas muté est rejeté, le coffre reste valide.
      Cette faille n'aurait JAMAIS été trouvée en regardant Δ tout seul.
      C'est tout l'intérêt d'une référence extérieure.

  VERDICT : 6 épreuves de conformité sur 6 passées, 2 limites assumées et
  chiffrées, 1 faille réelle découverte dans Δ et corrigée.

Δ-BRIDGE V1.0 — LE PONT : REGISTRES, CODECS, CONDENSATEURS EXACTS

  python bench_bridge.py   (journal : bench_bridge_log.txt,
                            résultats : resultats_bridge.json)
  données : btc_reference.json + btc_transactions.json

  L'IDÉE DE RENÉ : ne pas envoyer le calcul tout droit. L'EXTRAPOLER, le
  mettre en parallèle, sortir les empreintes par ce chemin-là, puis
  regarder quels composants manquent encore.

  Le juge reste Bitcoin : tout chemin bâti ici doit redonner, au bit près,
  les hashs officiels de blocs réels. Un chemin élégant qui donne un hash
  faux ne vaut rien.

  1. CONFORMITÉ DU PONT ..................................... 4 blocs / 4
     Et 256 nonces traités DE FRONT, comparés un par un à hashlib : exacts.
     Les 64 constantes de SHA-256 sont RECALCULÉES (racines carrées et
     cubiques des 64 premiers nombres premiers), jamais recopiées : aucune
     faute de frappe n'est possible.

  2. L'EXTRAPOLATION (midstate) — LE VRAI GAIN
     64 des 80 octets de l'en-tête ne bougent pas d'un essai à l'autre. On
     les compresse UNE fois et on garde le registre : 3 compressions
     deviennent 2.
       gain théorique ×1,50 | gain mesuré ici ×1,11
     POURQUOI L'ÉCART, mesuré et non supposé :
       une compression de 64 octets .......  45 ns
       l'appel Python autour .............. 287 ns
     On économise 45 ns de travail utile par essai, mais chaque essai
     traîne ~574 ns de plomberie qui ne bouge pas. Le gain de structure est
     entier ; c'est le langage qui en reprend une part. En C, on retrouve
     le ×1,5.
     ET C'EST LA LOI DE Δ, VÉRIFIÉE SUR UN TERRAIN ADVERSE : le gain ne
     vient pas d'un calcul plus malin, il vient de la STRUCTURE du message.

  3. LE PONT EN PARALLÈLE — RÉSULTAT NÉGATIF, GARDÉ
     N messages de front, 64 tours vectorisés : EXACT, mais 2,4x à 6,5x
     plus LENT que hashlib. Les 64 tours font ~1 300 passages numpy sur le
     tableau, chacun relisant la mémoire ; hashlib garde ses 8 mots dans
     les registres du processeur et ne sort jamais du cache L1.
     Le pont ne sert donc PAS à aller plus vite. Il sert à OUVRIR la boîte :
     sans registre exposé, pas de midstate — donc pas le gain du §2.

  4. CONDENSATEUR EXACT À LONG CHIFFRE
     20 000 empreintes de 256 bits rangées en 0,1 ms, restitution EXACTE au
     bit près, 8 membres de 32 bits par chiffre.
     LA MÊME EMPREINTE PASSÉE PAR LE CONDENSATEUR À PERTE DE Δ18 :
       rangée en octets,  16 bits : 0/32 faux  -> intacte
       rangée en octets,   8 bits : 0/32 faux  -> intacte
       rangée en octets,   4 bits : 28/32 faux -> détruite
       rangée en membres, 16 bits : 6/8 faux   -> détruite
       rangée en membres,  8 bits : 6/8 faux   -> détruite
     NUANCE ASSUMÉE : il est FAUX de dire que Δ18 détruit toujours une
     empreinte — octet par octet à 8 bits, elle survit (256 valeurs dans
     256 niveaux). Mais rangée comme il FAUT la ranger pour la comparer,
     en membres de 32 bits, la destruction est immédiate. Et octet par
     octet coûte 4 fois plus de place pour zéro gain.
     RÈGLE DU PONT : vers la cryptographie, c'est EXACT ou rien.

  4bis. LA CHAÎNE SANS CONFIANCE (codec varint + txid)
     Nouveau composant : lecture d'une transaction BRUTE (CompactSize,
     entrées, sorties, témoins SegWit retirés) et recalcul du txid.
     Vérifié sur les 4 transactions du bloc 100 000 :
       octets bruts -> txid -> racine de Merkle -> en-tête -> hash du bloc
     CHAÎNE COMPLÈTE VÉRIFIÉE. Avant ce codec, on CROYAIT l'explorateur sur
     les txid ; maintenant on les recalcule. C'est la différence entre
     vérifier et faire confiance, et elle tient en quelques lignes.

  5. JUGER N EMPREINTES D'UN SEUL GESTE
     20 000 comparaisons à la cible : 335 µs par le condensateur contre
     4 927 µs par entiers Python -> x15 à x20, verdicts identiques.

  6. COMPOSANTS — CE QUI EST LÀ, CE QUI MANQUE
     FAIT     registre d'état SHA-256 (les 8 mots sortis de la boîte noire)
     FAIT     codec d'expansion W[0..63]
     FAIT     codec d'en-tête 80 octets
     FAIT     midstate / extrapolation
     FAIT     condensateur EXACT à long chiffre (128 à 512 bits)
     FAIT     comparateur de cible vectoriel
     FAIT     codec varint (CompactSize) + recalcul de txid
     MANQUE   Base58Check (adresses 1...)
     MANQUE   Bech32 / Bech32m (adresses bc1...) — son code BCH DÉSIGNE le
              caractère fautif : exactement l'esprit de l'ECC de Δ9
     MANQUE   registre secp256k1 (ECDSA / Schnorr) — vérifier une SIGNATURE
              et non plus seulement une empreinte. C'est là que
              l'arithmétique modulaire à long chiffre servirait vraiment,
              et là aussi qu'une bibliothèque éprouvée doit prendre le relais
     MANQUE   arbre de Merkle des témoins (SegWit, depuis 2017)

  7. CE QUE L'ASTUCE A DONNÉ, ET CE QU'ELLE N'A PAS DONNÉ
     GAGNÉ  le midstate (x1,5 théorique, x1,11 ici), conforme sur 4 blocs
     GAGNÉ  le comparateur de cible, x15 à x20
     GAGNÉ  la chaîne sans confiance
     GAGNÉ  un registre, trois codecs, un condensateur exact
     PERDU  le chemin vectorisé, 2,4x à 6,5x plus lent que hashlib
     INCHANGÉ : 1,4e10 années pour trouver un bloc avant l'astuce,
     1,3e10 après. Gagner 8 % sur l'infini, c'est toujours l'infini.
     Le pont rend Δ plus CAPABLE ; il ne rend pas la montagne plus basse,
     et aucune astuce ne le fera : SHA-256 est bâti pour n'offrir aucune
     prise. C'est précisément ce qui le fait tenir debout depuis 17 ans.

Δ-FRACTAL V1.0 — CHAQUE GRAIN PORTE LE CONCEPT ENTIER (delta_fractal.py)

  python bench_fractal.py  (journal : bench_fractal_log.txt,
                            résultats : resultats_fractal.json)

  L'IDÉE DE RENÉ : « sur chaque micro-qubit tu octroies ce calcul dans son
  intégrité ; le concept complet fera l'infini ».

  CE QUI A ÉTÉ BÂTI
    Une grappe n'est plus une DONNÉE, c'est un ÊTRE COMPLET : il calcule sa
    part, porte son sceau, et sait prouver qu'il est bien lui. Et un paquet
    de ces êtres EST un être de la même espèce — même interface, même sceau,
    même preuve. Donc on recommence. Indéfiniment.
        cellule -> nœud -> nœud de nœuds -> ...
    Quatre gestes identiques à chaque étage :
        valeur()  sceau()  preuve(i)  verifier()

  1. CONFORMITÉ : 1 024 grains, profondeur 11, écart avec le calcul direct
     EXACTEMENT 0.0 (pas « petit » : nul).

  2. LA PREUVE TRAVERSE TOUS LES ÉTAGES : 10 empreintes, 160 octets, pour
     prouver qu'un grain parmi 1 024 appartient bien à la racine. Relire les
     1 024 grains coûterait 1 048 576 octets -> x6 554. Acceptée sur le vrai
     sceau, REFUSÉE sur un sceau inventé.

  3. À QUELLE FINESSE LE CONCEPT COMPLET TIENT-IL ? (la vraie question)
     Chaque grain porte 16 octets de sceau, quoi qu'il transporte.
        grain    1 nombre  ->  surcoût  997 %   le concept écrase la donnée
        grain    8 nombres ->  surcoût  125 %   le concept écrase la donnée
        grain   16 nombres ->  surcoût   62 %   coûteux
        grain   64 nombres ->  surcoût   16 %   raisonnable
        grain  256 nombres ->  surcoût  3,9 %   quasi gratuit
        grain 1024 nombres ->  surcoût  1,0 %   quasi gratuit
        grain 4096 nombres ->  surcoût  0,2 %   quasi gratuit
     L'INFINI NE SE GAGNE PAS EN DESCENDANT TOUJOURS PLUS FIN. Sous 16
     nombres par grain, la signature pèse plus que ce qu'elle protège.
     Au-dessus de 256 c'est quasi gratuit, mais on perd en finesse de
     désignation. Le bon grain est entre les deux, et il se MESURE.

  4. LA PREUVE FACE AU NOMBRE — c'est ici que l'infini se gagne
        16 grains ->  64 o de preuve |    2 Kio de données
       256 grains -> 128 o           |   32 Kio
     4 096 grains -> 192 o           |  512 Kio
    65 536 grains -> 256 o           | 8 192 Kio
     La donnée est multipliée par 4 096, la preuve passe de 64 à 256 octets.
     Elle grandit comme le LOGARITHME, pas comme le nombre.
     CE N'EST PAS QU'ON RANGE L'INFINI : C'EST QU'ON LE PROUVE EN QUELQUES
     OCTETS. 2^64 grains (18 milliards de milliards) -> 1 Kio de preuve.
     2^256 -> 4 Kio. Au-delà de 2^16, c'est une EXTRAPOLATION de la loi
     log2(N)x16 — loi vérifiée sur les quatre points mesurés, mais
     matérialiser 2^64 grains n'est possible sur aucune machine, et je ne
     ferai pas semblant du contraire.

  5. UN GRAIN MENT : on modifie UN nombre de 1e-9 dans le grain 300 sans
     toucher à son sceau — le cas le plus sournois. L'arbre le voit, désigne
     le grain 300, en suivant 9 branches sur 512, en 3,3 ms. La preuve de ce
     grain est désormais REFUSÉE. Sur un arbre sain : aucun faux positif.

  6. CONTRE-ESSAI : deux grains de sceau identique -> arbre muté -> REJET.
     Le correctif trouvé sur Bitcoin protège maintenant CHAQUE étage. Une
     faille corrigée une fois est corrigée partout : c'est le vrai bénéfice
     d'une architecture qui se répète.

  UN DÉFAUT RÉEL TROUVÉ ET CORRIGÉ EN ROUTE
     La première version comparait le sceau RANGÉ au lieu de le RECALCULER
     sur la donnée. On pouvait donc modifier un grain sans que rien ne
     bronche : §5 renvoyait « aucun fautif » sur un arbre corrompu. Un sceau
     qui ne relit pas ce qu'il scelle ne protège rien — il confirme
     seulement qu'on l'a bien rangé. Corrigé (recalculer() récursif), puis
     remesuré.

  CE QUE LA FRACTALE NE DONNE PAS
     - de la place : l'arbre ne range rien de plus, il PROUVE ;
     - de gain sous 16 nombres par grain ;
     - la détection d'une corruption reste en O(N) : vérifier, c'est relire,

Δ-QUTRIT V1.0 — Δ EN DIMENSION 3, ET LA MESURE D'ATLAS REJOUÉE

  python bench_qutrit.py   (journal : bench_qutrit_log.txt,
                            résultats : resultats_qutrit.json)
  référence extérieure : ATLAS, arXiv 2603.26463, « Measurements of
  Z-boson pair entanglement in decays of Higgs bosons », 4,7 sigma,
  annoncé le 23 septembre 2026.

  POURQUOI CETTE EXTENSION
    Depuis Δ1, tout le projet travaille en dimension 2 : des qubits, et
    un rang de Schmidt qui ne peut pas dépasser 2 sur une coupure
    élémentaire. Les bosons Z sont massifs et de spin 1 : TROIS états de
    polarisation. Le papier d'ATLAS les nomme lui-même « spin qutrits ».
    Pour deux qutrits, X ne peut pas dépasser 3. Le X de Δ n'est donc pas
    un réglage libre : la dimension locale le borne.

  1. L'ÉTAT, EXACT
     Le Higgs a un spin NUL ; deux bosons de spin 1 n'ont qu'un seul état
     de spin total nul possible :
         |H> = ( |+1,-1> - |0,0> + |-1,+1> ) / racine(3)
     coefficients de Schmidt : 0,577350 / 0,577350 / 0,577350 (tous égaux)
     X = 3, le maximum. Entropie = 1,098612288668 nats.
     ln(3) = 1,098612288668 -> écart 2,2e-16, la limite du flottant.
     L'état est MAXIMALEMENT intriqué.

  2. LE TEST D'ATLAS REJOUÉ DANS Δ
     état du Higgs      : X = 3, coupure autorisée NON
     état produit       : X = 1, coupure autorisée OUI
     ATLAS a testé exactement cette hypothèse sur le ciel — « l'état
     est-il séparable ? », c'est-à-dire « X vaut-il 1 ? » — et le
     détecteur a répondu NON à 4,7 sigma. Le test de découpage de Δ1
     répond NON pour la même raison : le deuxième coefficient de Schmidt
     vaut 0,577350 et ne tombe pas sous la tolérance.

  3. LA SYMÉTRIE — Δ10 APPLIQUÉ À LA PHYSIQUE RÉELLE
     Une seule charge existe : m1 + m2 = 0.
     amplitudes possibles 9, réellement non nulles 3 -> x3.
     Six amplitudes sur neuf ne sont pas « petites » : elles sont
     INEXISTANTES. Dans Δ10 on rejette une porte qui viole la charge ;
     ici c'est la nature qui refuse, et c'est cette contrainte qui
     FABRIQUE l'intrication. L'état n'est pas intriqué par hasard : il
     l'est parce qu'une symétrie lui interdit d'être autre chose.

  4. JUSQU'OÙ L'INTRICATION RÉSISTE (critère de Peres-Horodecki)
     négativité de l'état pur : 1,000000000000 (théorie (d-1)/2 = 1)
        p = 1,00 -> 1,000000  INTRIQUÉ
        p = 0,40 -> 0,200000  INTRIQUÉ
        p = 0,26 -> 0,013333  INTRIQUÉ
        p = 0,25 -> 0,000000  séparable — Δ peut couper
     seuil cherché par dichotomie : p = 0,250004
     seuil théorique 1/(d+1)      : p = 0,250000   écart 3,8e-06
     C'EST LE PONT ENTRE LA PHYSIQUE ET LE CANON DE Δ : eps est ce qu'on
     a le droit de PERDRE, et la nature fixe ici le point exact où la
     perte devient totale. Au-dessus de p = 1/4, Δ n'a PAS le droit de
     découper, quelle que soit la tolérance qu'on lui donne. En dessous,
     le découpage devient légitime. Ce seuil n'est pas un réglage :
     c'est une frontière.

  5. CE QU'IL MANQUE À ATLAS POUR LA DÉCOUVERTE
     observé 4,7 sigma, attendu 4,9 ; seuil de découverte 5,0.
     La significativité croît comme racine(N) :
        5 sigma  -> x1,132 de données, soit +13 %
        7 sigma  -> x2,22
       10 sigma  -> x4,53
     Treize pour cent séparent « évidence forte » de « découverte ». Le
     HiLumi n'apportera pas une idée neuve, il apportera du VOLUME.

  CE QUE CE CALCUL NE DIT PAS, ET IL FAUT LE DIRE
     - Δ reconstruit l'état THÉORIQUE imposé par la symétrie, exactement.
       Il ne rejoue PAS l'analyse d'ATLAS : reconstruire les coefficients
       C depuis les angles des quatre leptons demande leur convention de
       normalisation des opérateurs tensoriels, que je n'ai pas. Leurs
       C(2,1,2,-1) = -0,71 +/- 0,45 ne sont donc pas comparables tels
       quels aux nombres ci-dessus.
     - l'étoile de ZZ* compte : à 125 GeV le Higgs ne peut pas produire
       deux Z réels (91 GeV chacun), l'un est virtuel. L'état réel n'est
       donc pas le singulet pur mais un mélange — d'où le modèle isotrope
       du §4, approximation DÉCLARÉE et non vérité du détecteur.
     - Δ ne prouve rien sur la nature. Il montre qu'un état contraint par
       une symétrie est forcément intriqué, et à quel point. C'est ATLAS
       qui a fait la mesure.

     Ce qui la fait apparaître DANS LES POIDS, c'est une CONTRAINTE qui
     rend le superflu coûteux.
     Et c'est exactement ce qu'on venait de voir au LHC : les deux bosons
     Z ne sont pas intriqués parce qu'ils se rencontrent, mais parce que
     le spin nul du Higgs LEUR INTERDIT d'être séparables.
     Dans les deux cas — un accélérateur de 27 km et un réseau de 64
     entrées — ce n'est pas le processus qui crée la structure.
     C'EST LA CONTRAINTE.

  CE QUE JE NE PEUX PAS AFFIRMER, ET JE NE L'AFFIRMERAI PAS : c'est une
  fidélité LOCALE. Le produit de 10^10 fidélités locales tend vers ZÉRO
  quelle que soit leur valeur. La fidélité GLOBALE d'une chaîne de dix
  milliards de sites n'est pas calculable — limite de principe.

  L'INTRICATION D'ORIGINE, REMISE SANS RETOUCHE (test des îlots de Δ1)
        6 îlots sur 6 réellement intriqués, entropies 0,147 à 0,545 nats
        coefficients de Schmidt : 0,9045/0,4264 ; 0,8749/0,4844 ; etc.
        fusion par produit tensoriel : Schmidt 1,00 / 1,6e-16 / 2,1e-17
        -> reconnue SÉPARABLE, comme elle doit l'être.
  Un îlot qui se recoupe n'était pas intriqué, un îlot qui refuse la
  coupure l'est. Rien n'a bougé depuis le premier jour.

  LES TÉRAFLOPS — ET LA LOI DU GAIN
        b      rang moyen   gain mesuré   b/(2·rang)
        128       2,10          30,4        30,5
        512       4,47          57,3        57,3
       1024       5,84          87,7        87,7
       2048       8,02         127,7       127,7
    -> gain = b / (2 x rang), EXACT aux quatre points.
    -> le rang croît comme ~0,36·racine(b), donc gain ~ racine(b)/0,72.
    MEILLEUR MESURÉ : 0,503 Tflops équivalent-dense à b=2048.
    Pour 1 Tflops équivalent il faudrait b ≈ 32 000 — soit 8 Gio par SVD
    d'initialisation, et cette machine en a 7,8 au total. [EXTRAPOLÉ]
    Limite de MOYENS ; sur une machine de 128 Gio la loi dit que ça passe.

  CE QUE « ÉQUIVALENT-DENSE » VEUT DIRE : Δ ne fait pas tourner le
  processeur plus vite, il fait MOINS d'opérations pour le même résultat.
  Le téraflops équivalent compte les opérations ÉVITÉES. C'est légitime
  à condition de le nommer — un flops machine et un flops évité ne sont
  pas la même monnaie.
